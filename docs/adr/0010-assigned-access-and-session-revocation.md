# ADR 0010 — 활성 배정 기준 조회와 계정 변경 시 세션 회수

- 상태: 채택(2026-11-10 사용자 결정)
- 관련 이슈: https://github.com/team-khfc/Security-Advisor-Back/issues/11

## 결정 배경

FUNCTIONAL_SPEC 3장의 같은 분야 미배정 담당자 조회 허용과 3-2장의 사업 공통 정보 접근 제한이 혼재했다. 신청·감사 이력 목록은 활성 배정으로 제한했지만 상세·문서함·통계는 담당자 전체에게 열려 있었다.

사용자가 **배정된 신청만 조회하도록 목록·상세·문서·이력을 통일**하기로 선택했다. 이 결정은 같은 분야 미배정 조회 허용보다 우선하며 공식 공통 문서의 다음 동기화에 반영한다.

## 조회 범위

| 역할 | 신청·문서·이력 | 사업 공통 정보 | 업무 지표 |
|---|---|---|---|
| APPLICANT | 본인 신청 | 본인 사업 | 불가 |
| INFRA·SECURITY | 현재 역할과 분야가 일치하는 활성 배정 신청 | 하위 신청 중 하나 이상에 위 배정이 있는 사업 | 불가 |
| ADMIN | 전체 조회 | 전체 조회 | 허용 |

- 사업·요청함의 관련 신청 요약도 조회 가능한 신청만 반환한다. 같은 사업의 형제 신청 배정은 다른 신청의 상세 접근권이 아니다.
- 조회 불가 자원은 404로 존재를 숨긴다. 목록은 제외하며 집계에도 포함하지 않는다. 역할 전용 기능 거부는 403, 만료·회수된 세션은 401이다.
- 신청 생성·신청자 편집은 APPLICANT만 한다. 담당자·관리자가 조회할 수 없는 본인 미배정 신청을 생성하는 우회도 허용하지 않는다.
- 방화벽 규칙 목록·기록도 해당 신청의 접근 범위를 적용한다. 실제 장비 제어는 추가하지 않는다.
- 관리자 조회 권한은 담당자 검토 권한을 부여하지 않는다. 기존 배정 검사·자기 배정 금지는 유지한다.

## 기존 세션 회수

- 계정에 `session_version`을 저장한다. 역할·활성 상태의 실제 변경만 세대를 증가시키며 멱등 요청·연락처·로그인 기록은 증가시키지 않는다.
- 로그인 시 역할·세대를 불변 principal에 저장한다. 매 요청은 업무 처리와 CSRF 검사 전에 DB의 활성 상태·역할·세대를 검사한다. 실패하면 세션을 무효화하고 401을 반환한다.
- 비활성화→재활성화, 역할 변경→원복 사이에 요청하지 않은 옛 세션도 차단한다. 기존 세션에 새 권한을 자동 부여하지 않으며 재로그인이 필요하다.
- 계정 쓰기는 행 잠금으로 직렬화한다. 로그인 성공·실패 기록이 동시에 변경된 역할·세대를 덮어쓰지 않는다. 권한 변경·세대 변경·감사 기록은 같은 업무 트랜잭션이다.
- 활성 배정은 매 조회 검사한다. 재배정으로 권한을 잃은 담당자는 로그인 세션 자체가 유효해도 그 신청을 열 수 없다.

## 호환과 검증

API 응답 구조는 바뀌지 않는다. 기존 계정은 세대 0으로 이행하며 데이터·배정·업무 이력을 삭제하지 않는다. DB 복구 시 새 컬럼을 보존한 상태로 이전 앱을 기동할 수 있으나, 이전 앱에는 이 권한 차단 기능이 없다.

검증은 `AccountSessionApiTest`, `RequestAccessApiTest`, 기존 업무 통합 검사와 `tools/verify_access_sessions.mjs`로 수행한다. 도커 재현 결과는 [검증 기록](../ACCESS_SESSION_20261110.md)을 따른다.
