# ADR 0008 — 최종 서술 확인과 제출본 보존

- 상태: 채택 (2026-11-10)
- 관련: F-06·F-07, Back #3 / Front #30

기존 `draft-generations`는 참고 문서를 만들었지만 사용자 확인과 제출 검사에 연결되지 않았다. 최종 서술은 신청의 작성·제출 책임이므로 request의 `FinalDraft`로 관리하고, document는 AI 생성과 출력만 담당한다. 컨텍스트 간 순환 의존은 만들지 않는다.

1. AI 생성과 직접 작성 모두 확인 전 상태로 시작한다. 확인 요청은 신청자 본인·3단계 최종 검토에서만 받는다. 사람의 수정 후에도 AI 원문·모델·출처를 보존한다.
2. 생성 당시 게시본·사업·신청·답변 revision으로 원본 지문을 만든다. 답변 변경 이벤트는 확인을 무효화한다. 장시간 AI 요청 중 다른 초안이 생성되어도 최신 초안을 덮어쓰지 않는다.
3. 확인은 초안 revision을 검사한다. 제출·초안 생성은 신청 단위 잠금으로 순서를 정하고, 제출 중 초안 변경은 낙관적 버전 검사로 거부한다.
4. 생성한 초안이 있으면 최신·확인 상태여야 제출 가능하다. 기존 API의 서술 없는 신청은 답변만 제출하는 호환 경로를 유지한다. 새 화면은 AI 또는 직접 작성 후 확인을 요구한다.
5. 제출본 JSON의 `finalDraft`에 확인한 본문, AI 원문, 출처, 모델, 확인자·시각과 원본 지문을 복사한다. 이후 현재 초안이나 답변은 과거 제출본을 바꾸지 않는다.
6. 정식 PDF·Markdown·미리보기 데이터는 제출본 지정 시 그 스냅샷의 최종 서술과 제목을 사용한다. 최종 서술은 PDF에서 페이지를 나누어 출력한다. HWPX 지원은 이번 범위에 포함하지 않는다.

API: `GET /api/security-requests/{id}/final-draft`(미작성 204), `POST …/final-draft-generations`(AI), `POST …/final-drafts`(직접 작성), `PUT /api/final-drafts/{id}/confirmation`(수정·확인). 기존 문서 생성·출력 API는 유지한다.

자동 검증은 `FinalDraftTest`, `SubmissionApiTest.finalDraftAndPdf` 및 기존 문서·권한·업무 테스트에 포함한다. 실제 모델과 브라우저 검증은 Front의 최종 보고서 검증 기록에 분리한다.
