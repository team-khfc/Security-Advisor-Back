# 0012 — 지식 초안·게시본 분리와 신청별 지표 정책

상태: 채택 · 2026-11-10 · Back #19 / Front #52

## 결정

공개 지식 조각과 기관 비공개 정보는 독립된 지식 게시본으로 관리한다. 기존 질문·기한 설정의 게시 주기와 분리하며 `business_cases.knowledge_publication_id`를 생성 시 고정한다. 이전 사업은 마이그레이션 시 기존 자료 전체의 초기 사본 v1에 연결한다. 사업에 추가한 서류도 같은 기준을 사용하며 제출 사본에 지식 게시본 ID를 기록한다.

기존 지식·비공개 정보 테이블은 편집 초안이다. 기존 POST/PUT은 더 이상 즉시 업무에 적용되지 않으며 명시적 게시가 필요하다. 관리 초안 목록·단건·변경 비교·게시 이력·전체 사본 API는 ADMIN만 읽는다. 공개 검색·도움말·인터뷰·AI 제안·담당자 질의는 게시된 사본만 사용한다. Front와 함께 배포한다.

항목 수정은 항목의 revision, 게시 메모·게시는 초안 전체 revision을 검사한다. 모든 저장·게시는 단일 초안 행의 잠금 안에서 직렬화한다. JPA가 revision을 올리며 별도 변경 순번으로 동일 시각·동일 사용자 편집도 감지한다. 다른 관리자가 변경한 뒤의 저장·게시는 409이며 검토를 다시 해야 한다. 내용 차이가 없는 게시도 거절한다. 수정 대신 사용 중지 상태를 게시하며 이력을 삭제하지 않는다.

비공개 사실의 **값**은 사업에 고정된 사본을 사용한다. **열람 권한**은 고정 사본과 현재 게시본의 활성·역할 권한을 모두 만족해야 한다. 따라서 현재 게시본에서 사용 중지 또는 역할 축소 시 과거 사본도 조회에서 제외한다. ADMIN은 관리 권한으로 전체 사본을 읽고 APPLICANT는 비공개 제안을 받지 않는다. 이미 사람이 입력·확인한 신청 값과 이미 생성된 문서·질의 이력은 별도 업무 기록이며 이 기능으로 소급 삭제하지 않는다.

비공개 사본 조회는 접근 감사를 남기되 원문·속성·변경 메모를 감사 요약에 복제하지 않는다. 공개 근거와 기관 사실은 기존 LLM 입력 경계에서 계속 분리한다. 링크는 저장만 하며 서버가 원문 URL을 가져오지 않는다.

업무 지표는 ADMIN의 읽기 전용 계산 결과다. 개인별 순위, 임의 수치 저장·편집·게시 기능은 제공하지 않는다. 기한 임박 상태와 단계별 소요 영업일은 각 사업에 고정된 질문·기한 게시본의 공휴일로 계산한다. 분모가 없으면 null이며 화면은 ‘산정할 자료 없음’으로 표시한다.

## 검증과 한계

- PostgreSQL 통합 검사: 초안 미노출, v1·v2 사본 고정, 기존 사업 추가 신청, 동시 저장 200/409, 게시 충돌, 역할 축소의 과거 사본 차단, 관리자 외 3역할 접근 거부, 페이지 이동·입력 검증.
- 지표 회귀 검사: 공휴일이 다른 두 사업의 평균 1.5영업일, 같은 마감일의 임박/기한 내 분류 차이, 현재 설정 미참조.
- 도커 사용자 검증은 Front의 `docs/KNOWLEDGE_INSIGHTS_20261110.md`에 기록한다.
- 공개 검색은 ADR 0006의 PostgreSQL 전문검색이다. 이번 범위는 원문 파일 수집·벡터 색인·LLM 구성 관리가 아니다. 지식 사본의 JSON 배열을 조회하므로 큰 자료 규모에서는 별도 게시본별 검색 인덱스로 확장해야 한다.
- 지표는 기관 전체 이력을 메모리에서 집계하는 기존 방식을 유지한다. 대규모 이력에서는 DB 집계·기간 필터와 성능 검증이 후속 과제다. 과거 이력의 비공개 원문 자체를 지우는 기능은 없다.
