# ICT인프라 서버·네트워크·운영 검토

- `infrastructure-plan` JSON에 `schemaVersion: 2`, `servers`, `operations`, `checklist`, `draft`, `aiPending`을 추가한다. 기존 저장본과 제출 스냅샷은 새 속성이 없으면 이전 형식으로 읽는다.
- 서버는 ID로 통신 구간에 연결한다. 서버명·IP·망 구간은 서버가 기준이며 저장 시 백엔드에서 다시 해석한다. 끊어진 연결과 중복 식별자는 거부한다.
- 임시 저장은 누락값을 허용하지만 입력된 주소·포트·프로토콜·날짜 형식은 검사한다. 임시 저장은 기존 공통·서류 답변에 동기화하지 않는다. 서버/구간/운영/체크리스트/AI 미확인 상태와 근거는 보존하며 완료된 협의는 재검토 대상이 된다.
- 확인 저장은 서버명·용도·운영 형태·주소·망 구간, 완성된 통신 구간, 운영 책임·망 분리·관리 접속 설명 및 4개 구성 체크리스트를 요구한다. CPU·메모리·저장공간·OS·DB와 백업·이중화·모니터링은 알려진 범위에서 입력하며 없는 값을 추측하지 않는다.
- AI 서버 사양은 기존 제안 API에 `target: SERVERS`를 보낸다. 각 필드의 값과 인용을 첨부 텍스트/담당자 설명과 대조한다. 제안은 자동 저장하지 않으며 선택 적용 후 서버별 확인이 필요하다. 임시 저장 중 미확인 AI 서버는 문서에도 미확인으로 표시한다.
- `requireCurrent`에서 임시 저장/AI 미확인 상태의 협의 완료·제출을 차단한다. 신규 서버·운영 정보도 문서와 제출 스냅샷에 포함한다. 이미 제출한 문서는 그 제출본 내용을 사용한다.

검증: 관련 망 구성 API(기존 형식 포함), 서버 연결·임시 저장·확인 저장·협의 차단·문서 반영, 근거 없는 AI 서버 사양 제거, OpenAPI 내보내기 통과. 실제 외부 모델 호출 및 실장비 변경은 하지 않았다.
