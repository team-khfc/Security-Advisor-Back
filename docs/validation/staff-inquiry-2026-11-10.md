# 담당자 AI 질의 검증 (2026-11-10)

F-04의 배정된 ICT인프라·정보보안 담당자 개인 대화를 연결하기 위한 서버 보완이다. 기존 문의 API 경로·DTO와 OpenAPI 계약은 유지한다. 프론트 이슈: team-khfc/Security-Advisor-Front#42.

## 구현 범위

- 현재 신청의 답변·사업 정보, 같은 사업의 최근 업로드 3개와 완료된 AI 요약 3개, 공개 지식, 역할로 필터링한 기관 사실을 수집한다.
- 원문은 기존 추출기의 앞 20,000자 중 질문 단어 주변 최대 6,000자를 사용한다. 근거 설명에 파일명과 추출 문자 범위를 남기고 읽기 실패를 명시한다.
- 근거의 태그와 질의 당시 설명을 기존 JSONB 컬럼에 저장한다. 이전 문자열 태그 배열도 읽으며 과거 설명을 현재 자료로 만들어 채우지 않는다.
- 작성자뿐 아니라 현재 역할·활성 배정도 재검사한다. 이전 역할의 대화 제목은 목록에서 제외한다.
- 확인된 담당자 입력값은 기관 사실 블록에 포함한다. 출처 없는 IP는 가리고 알 수 없는 근거 태그는 제외하면서 경고 표시한다.
- 잘못된 AI 응답은 503으로 처리하고 질문·답변을 부분 저장하지 않는다.
- 신청 답변·검토·할당·확정 상태를 변경하지 않는다.

## 자동 검사

- Java 25의 `gradlew.bat spotlessApply check`: 157개 통과, 조건부 2개 제외(별도 live 제안 테스트와 OpenAPI export).
- OpenAPI 일치 검사, ArchUnit 및 PostgreSQL Testcontainers 검사 포함.
- 추가한 9개 단위 검사: 원문 범위·파일 수 제한·불가 문서·미확정 요약, 근거 설명 재조회와 이전 저장 형식, 미등록 IP·근거 태그, 잘못된 응답의 미저장, 배정 해제·역할 변경·다른 소유자·이전 역할 제목 비노출.
- 규칙 문서 9종 점검 통과.

## 도커 실제 AI 검사

- 로컬 통합 도커의 별도 합성 사업 17 / 방화벽 신청 29. 문서 1, 분석 작업 1.
- 기존 DB 설정의 실제 모델로 문서를 요약한 뒤 담당자 UI에서 INFRA 2회, SECURITY 1회 질문했다.
- 원문 식별 문구 `별빛검증-731`, 기록 보관 180일, 운영 담당자 사전 승인, HTTPS 443을 근거 U1과 D1로 확인했다. D1은 미확정으로 표시된다.
- 재로그인·도커 재배포 후에도 INFRA 대화 1(4개 메시지), SECURITY 대화 2(2개 메시지)가 유지되고 각자의 목록만 반환된다.
- 다른 소유자 메시지 조회 404, 신청자 목록 조회 403, 미배정 신청 목록 조회 403.
- 질문 전후 신청 상세 전체 응답을 비교하여 동일함을 확인했다. 실제 장비는 변경하지 않았다.

## 한계

전체 문서 검색·OCR 기능은 아니다. 최근 파일·추출 길이 제한을 프론트에 안내한다. 저장하는 근거 설명은 질문 시점의 출처이며, 자료 변경 후에는 다시 질의해야 한다. 모델 답변은 참고이며 기관의 최종 판단을 대신하지 않는다.
