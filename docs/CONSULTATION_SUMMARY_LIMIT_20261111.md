# 협의 요약 출력 중단 진단과 수정

## 재현 근거

심사용 합성 신청의 기존 입력·프롬프트를 OpenRouter DeepSeek V4.1 Flash에 temperature 0.2 / max_tokens 4096으로 전달했다. 첫 재현 호출에서 `finish_reason=length`, completion_tokens=4096, reasoning_tokens=4065, 실제 응답 본문 52자와 불완전 JSON을 확인했다. 키·응답 원문은 로그에 남기지 않았다.

이전 사용자 흐름의 최초 실패 응답은 보관되지 않아 동일 원인이라고 단정할 수 없다. 다만 같은 조건에서 출력 한도가 추론으로 소진되는 실패를 재현했으며, 기존 코드는 JSON 파싱 오류·구조 오류·근거 오류를 모두 같은 '근거가 연결된 요약' 메시지로 처리했다.

## 수정

- Spring AI의 응답 종료 사유를 확인해 `length` / `max_tokens`로 잘린 응답을 모든 업무에서 저장 전에 거부한다. 출력 한도와 추론 토큰 설정을 안내한다.
- JSON/구조 오류와 실제 근거 검증 실패를 구분한다. 로그에는 모델 참조·신청 ID·실패 종류만 기록한다.
- 요약 지시는 핵심 3~5개, 항목당 300자·근거 1~6개로 간결하게 제한한다. 서버의 기존 유효성 상한은 유지한다.
- 현재 확인된 값을 기관 사실 블록에도 제공한다. 기존에는 본문에 확인된 서버 정보가 있으면서 기관 사실 블록은 비어 있어 서로 충돌하는 지시가 전달됐다. 미확인 값은 확정 사실로 제공하지 않는다.
- 존재하지 않는 근거, 근거 없는 IP, 비어 있는 근거, 원본 변경 충돌 검사는 유지한다. 무조건 재시도·잘못된 항목 제거 후 저장 같은 우회는 하지 않는다.

## 모델 설정

심사용 배포의 관리자 설정에 `DOCUMENT` 전용 DeepSeek 구성(8192토큰, 우선순위 4)을 추가한다. 기존 인터뷰·일반 요약·담당자 질의의 4096토큰 구성은 유지한다. API로 변경하여 설정 이력이 남으며, 새 심사용 설치에도 같은 설정을 생성한다. 이 수치는 모델별 운영 설정이지 모든 모델의 성공을 보장하는 고정 규칙은 아니다.

## 검증

집중 회귀 검사: 출력 한도(본문 유무·닫힌 JSON 포함) 거부, 정상 종료 응답, 정상 근거 저장, 불완전 JSON/구조/알 수 없는 근거/비어 있는 근거/새 IP 거부, 원본 충돌, 실패 시 저장·자동 재호출 없음. 실제 AI 재검증 결과는 배포 저장소의 `docs/JUDGE_VALIDATION.md`에 기록한다.
