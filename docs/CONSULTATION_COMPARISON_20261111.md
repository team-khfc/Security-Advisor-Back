# 협의 결과 비교와 AI 요약

## 동작

- 협의 요청 트랜잭션에서 사업·신청 답변과 서버·통신·운영 정보의 기준본을 추가 전용 `consultation_records`에 저장한다. 재요청하면 새 기준본을 만들고 이전 기록은 보존한다. 조회는 최근 협의 요청 이후 기록을 표시한다.
- 담당자 개별·일괄 답변 입력, 확인, 구성 임시·확인 저장의 변경 전·후 값과 이름·당시 역할·시각을 기록한다. 공통 사업 항목은 관련 미제출 신청에 연결한다. 신청자 답변 수정도 구분해 기록한다.
- 서버·통신 구간은 행 순서가 아닌 고유 ID로 비교한다. 기준본이 없는 기존 신청에는 현재 값과 도입 이후의 실제 기록만 표시하며 과거 변경을 추정하지 않는다.
- 기준본/변경 기록에는 업무 원문이 있으므로 일반 감사 이력과 분리하며 신청 상세와 동일한 조회 권한을 적용한다. 일반 감사 로그에 값 원문을 추가하지 않는다.
- `GET /api/security-requests/{id}/consultation-comparison`: 기준본·현재 값·기록·최근 요약.
- `POST /api/security-requests/{id}/consultation-summaries`: 본인 신청의 최종 검토 단계에서 `expectedFingerprint`와 함께 요청한다. DOCUMENT 모델을 사용하고 실제 항목 키의 근거 링크를 검증한다. 기존 요약은 프롬프트에 재투입하지 않는다.
- 요약 전·후 원본 기준을 비교하고 충돌은 409로 거부한다. 이후 원본 변경 시 화면에서 이전 요약 본문을 숨기고 재요약을 안내한다. AI 요약은 참고용이며 최종 보고서 확인·제출을 대신하지 않는다.
- 모델 입력이 20만 자를 넘으면 일부 기록을 누락해 요약하지 않고 직접 비교 안내를 반환한다. 모의 모델은 실제 분석을 수행하지 않았음을 명시한다.

## 검증

두 서류 유형의 기준본 없음→협의 요청→기준본 생성, 담당자 구성 변경 기록, 신청자 전용 요약 권한, 잘못된 원본 기준 거부, 모의 요약 근거 연결, 최종 검토 중 신청자 수정 후 요약 기준 불일치를 API 테스트로 확인했다. 구조 검사와 OpenAPI 내보내기도 통과했다.

프론트 비교·기존 신청 안내·근거 링크·오래된 요약 숨김 및 기존 상세 테스트 19건, 긴 AI 요청 프록시 테스트 5건, 타입·변경 파일 린트 검사를 통과했다. 실제 외부 모델 품질과 브라우저 로그인 흐름은 이번 간단 검증 범위에 포함하지 않았다.

신규 마이그레이션 `V202611110500__consultation_records.sql`을 적용해야 하며 기존 신청 데이터의 과거 기준본을 임의로 생성하지 않는다.
