# 질문·기한 정책 편집·게시 검증

검증일: 2026-11-10. Back 이슈 #17, Front 이슈 team-khfc/Security-Advisor-Front#50.

## 구현과 적용 범위

- 설치당 하나인 설정 초안을 저장하고 현재 게시본과 변경 내용을 비교한 뒤 새 게시본을 만든다. 초안 저장만으로 현재 업무에 반영하지 않는다.
- 질문 문구·도움말, 추가 질문의 응답 형식·작성 역할·범위·적용 서류·필수 여부와 협의·보완 응답·최종 확정의 영업일 기한 및 기관 공휴일을 검증한다.
- 처리 기한은 1~365의 정수이며 소수·문자열을 허용하지 않는다. 공휴일은 2000~2100년, 최대 366개다. 기한 임박 알림은 도메인 규칙대로 1영업일 전이다.
- 기본 질문은 최초 게시본을 기준으로 키·형식·역할·범위·적용 서류·필수 계약을 보호한다. 질문은 최대 200개, 문구는 200자, 도움말은 2000자, 변경 메모는 500자다.
- 쓰기 작업은 단일 설정 행의 잠금과 expectedRevision을 함께 사용한다. 실제 저장된 revision을 반환하며, 충돌은 409/REVISION_CONFLICT와 currentRevision으로 안내한다. 비교 후 다른 관리자가 저장해도 이전 비교 내용으로 게시할 수 없다.
- 게시자·게시 시각·메모·직전 버전을 게시본에 보존한다. 이력은 서버 페이지로 조회하며 게시 당시 비교 결과는 이후 초안 수정의 영향을 받지 않는다. 변경 내용이 없는 게시를 차단한다.
- 새 사업 건은 당시의 게시본을 고정한다. 기존 사업 건, 그 사업에 나중에 추가하는 신청, 이미 계산된 기한은 새 게시본으로 바뀌지 않는다.

새 마이그레이션은 게시 이력 메타데이터를 추가하고 설정 초안이 없는 설치에만 현재 게시본으로 초안을 생성한다. 과거 게시자의 정보를 추정하지 않으며, 메타데이터가 없는 이전 게시본은 그대로 표시한다. 조회 API는 초안을 생성하지 않는다.

## API

관리자 전용: `GET /api/configurations/current`, `PUT /api/configurations/{id}`, `GET /api/configurations/{id}/comparison`, `POST /api/configurations/{id}/publications`, `GET /api/publications?page=0&size=20`, `GET /api/publications/{id}/comparison`.

게시 이력 크기는 1~100, 페이지는 0 이상이다. 기존 `/api/publications/current`와 `/api/publications/{id}`의 인증된 사용자용 질문 조회 계약은 유지한다. Front는 Back의 `docs/api/openapi.yaml`을 복사해 사용한다.

## 실제 Docker 검증

합성 게시본 검증은 별도 프로젝트 `securityadvisor-configuration-qa`(Front 3011, Back 8091)의 독립 DB에서 수행했다. 외부 AI 대신 fake 모드이며 실존 정보와 실제 장비를 사용하지 않았다.

1. 실제 화면에서 v1 사업 건과 방화벽 신청을 만들고 협의를 요청했다.
2. 관리자가 질문 문구·도움말과 추가 질문을 편집하고 기한을 7/6/8영업일, 공휴일을 2026-11-11로 추가했다. 잘못된 키와 0일을 입력하면 저장하지 않는 것을 확인했다.
3. 두 편집 화면에서 같은 초안을 연 뒤 한쪽을 먼저 저장했다. 다른 쪽 저장은 409로 차단되고 입력은 남았다. 최신본 비교를 닫아도 입력이 보존되며 명시적으로 최신본을 선택해야 교체됐다.
4. 저장 → 변경 검토 → v2 게시 → v1·v2 이력·상세 조회를 화면에서 수행했다.
5. 새 사업 건을 만들어 새 질문과 문구를 확인하고 추가 질문 답변을 실제 저장했다. 기존 사업 건에 추가 신청을 생성해도 v1을 사용하는 것을 확인했다.

| 합성 자원 | 적용 게시본 | 협의 기한 |
|---|---|---|
| 기존 사업 1 / 방화벽 신청 1 | v1, 5영업일 | 2026-11-17 |
| 신규 사업 2 / 방화벽 신청 2 | v2, 7영업일 + 추가 공휴일 제외 | 2026-11-20 |
| 게시 뒤 기존 사업 1에 추가한 보안성검토 신청 3 | v1, 5영업일 | 2026-11-17 |

API 확인 28개 통과: 위 버전·질문·기한 유지 10개, 신청자·ICT인프라·정보보안의 관리 API 접근 차단 12개, 잘못된 기한 4개와 초안 보존·게시 이력 페이지 이동 2개.

검증한 동일 앱 이미지를 기존 `securityadvisor-integration`(Front 3001, Back 8081)에 반영했다. 기존 게시본 v1·초안 revision·신청 268건·계정 71개 보존과 새 API 8개 확인, 기존 알림·업무 인계·역할 접근 회귀 확인 17개를 통과했다. 기존 환경에서는 합성 v2를 게시하지 않았다.

## 자동 검사와 경계

- Java 25에서 `./gradlew spotlessApply check` 성공: 전체 179개 중 177개 통과, 환경 조건에 따른 기존 2개 생략. 실제 PostgreSQL의 동시 저장, 게시 직전 충돌, 게시본 불변, 권한·입력 검증을 포함한다.
- OpenAPI 내보내기 및 코드와 계약 일치 검사 성공.
- Docker 앱·Front 운영 빌드와 건강 상태 확인 성공.
- Front는 별도 저장소에서 306개 검사와 실제 화면·390px·키보드 검증을 수행했다. 화면 기록과 이미지는 Front의 같은 이름 문서에 있다.
- 문서 양식 파일 편집, 검토 단계 편집, 과거 게시본 자체 수정·기존 사업의 게시본 교체는 이번 범위에 포함하지 않는다. 게시된 스냅샷은 불변이다.
