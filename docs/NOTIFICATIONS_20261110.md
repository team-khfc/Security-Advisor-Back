# 업무 인계 알림·처리할 일 검증

2026-11-10. Back main `aedb5ab`, Front main `d077e7d`의 담당자 인계 기능에 이어 구현했다.

## 구현과 계약

재배정 알림, 역할 변경·계정/분야 등록 비활성 시 관리자 알림, 현재 담당자의 보완 답변·기한 알림을 연결했다. 목록·안 읽음 건수·읽음 처리는 현재 수신 권한을 공유한다. 알림은 업무 커밋 이후 생성하고 실패가 업무를 취소하지 않게 한다. 읽음 처리만으로 처리할 일이 사라지지 않는다.

`GET /api/notifications`는 페이지 응답으로 변경했고 `GET /api/todos`를 추가했다. Front와 함께 배포해야 한다. DB 마이그레이션 `V202611101700__notification_audience.sql`은 알림 대상 신청/수신 역할과 인덱스를 추가하며 기존 이력을 삭제하지 않는다. [결정 기록](adr/0011-notification-audience-and-todos.md), `docs/api/openapi.yaml` 참조.

- 106개 알림 전체 페이지/중복 없는 정렬, 읽음 시각 유지와 안 읽음 건수, 타인 읽음 404, 계정 비활성/역할 변경 기존 세션 401, 재로그인 후 기존 알림·할 일 제외, 분야 등록 비활성 제외.
- 인계 뒤 이전 담당자의 목록·건수·읽음 차단, 새 담당자의 보완 답변 수신·해소 후 업무 감소, 1영업일 전/기한 경과 알림과 재실행 중복 방지, 철회 후 업무 제외·기한 발송 중단.
- 브라우저: 관리자 계정에서 전임 ICT인프라 비활성 → 재배정 알림/할 일 증가 → 알림으로 신청 이동 → 새 담당자에게 재배정 → 관리자 할 일 감소. 새 담당자 로그인 → 인계 알림 열기 → 읽음 건수만 감소 → 처리할 일에서 담당자 협의 확인.
- 합성 신청 268만 지정해 2026-11-18 기준 기한 알림을 실행하고 새 담당자 화면에서 수신을 확인했다. 준비 실행 계정의 106건 알림은 마지막 6/6페이지까지 조회했다.
- 데스크톱 1280×900, 좁은 화면 390×844: 가로 넘침 없음. Enter로 알림 열기, 제목 초점, Tab으로 닫기 이동, Escape로 닫고 알림 버튼 초점 복원, 안 읽음 필터를 확인했다. 스크린샷은 Front 검증 문서에 있다.

검증에서 처음 읽음 처리와 재조회 시각의 나노초/마이크로초 차이를 발견해 수정하고 회귀 검사 및 Docker 재검증을 완료했다. 준비 실행 합성 신청 265/266과 최종 검증 신청을 보존했다. 신청 267은 검증 종료로 철회했고 268은 새 담당자 배정 상태다. 기존 실사용 신청과 장비는 변경하지 않았으며 외부 AI·메일·메신저를 호출하지 않았다.

## 재현

검증용 환경에서 `DEMO_ACCOUNT_PASSWORD`와 `SYNTHETIC_ACCOUNT_PASSWORD`를 지정하고 `node tools/verify_notifications.mjs`를 실행한다. `VERIFY_ORIGIN`(기본 localhost:3001), `VERIFY_ADMIN_USERNAME`, `VERIFY_OUTPUT`은 선택 사항이다. 합성 계정·신청을 새로 만들며 비밀번호·세션은 출력하지 않는다. 기한 재실행은 생성한 신청 하나로 제한한다.
